# Harbor Resource Operator: notes for Claude Code and other coding agents

Read this first, then `AGENTS.md` (kubebuilder layout rules), `CONTRIBUTING.md` (branches and releases) and `docs/REQUIREMENTS.md` (the design).

## What this project is

A Kubernetes operator that manages objects **inside** a running Harbor through its REST API v2.0: projects, robot accounts, replication endpoints and policies, project members, labels, immutable tag rules, webhooks, tag retention and the garbage collection schedule. It never installs, upgrades or backs up Harbor. That scope is deliberate: the archived `goharbor/harbor-operator` re-implemented the Helm chart and embedded three other operators, which made it too heavy to maintain. Do not add third-party operators, conversion webhooks in v1alpha1, or Harbor deployment logic.

## Layout

```
api/v1alpha1/            CRD types; common_types.go holds ConnectionRef, DeletionPolicy, condition reasons, Finalizer
internal/harbor/         thin Harbor client (client.go, types.go, errors.go); no generated client
internal/harbor/fake/    in-memory Harbor API for tests (mimics status codes, Location headers, error bodies)
internal/controller/     one controller per kind; common.go (connection resolution, errors, limiter), watches.go (dependency map funcs)
config/samples/          realistic examples; config/crd/bases and config/rbac/role.yaml are generated
charts/chart/            Helm chart generated by the kubebuilder helm plugin (regenerate with --force after manifest changes;
                         the plugin also rewrites .github/workflows/test-chart.yml, so revert that file afterwards)
test/e2e/                end-to-end suite on kind with the official Harbor chart
docs/REQUIREMENTS.md     design
```

## Conventions

- Harbor fields are mapped to camelCase spec fields; only fields set in spec are managed (unset fields are left as Harbor has them).
- Status and finalizer writes use `Patch` with `client.MergeFrom(base)`, never `Update`, and without an optimistic lock: a stale cache read once lost a freshly created robot ID on a conflict. Reconcilers read their own object uncached through `APIReader` (`getFresh`) for the same reason.
- Every controller: locate by stored ID, then by name; adopt only with `spec.adoptExisting`; `deletionPolicy` Retain or Delete; projects default to Retain and are never deleted while they hold repositories; Harbor 404 on delete is success.
- Errors: `terminal(...)` for user errors that wait for a spec change, `transient(...)` or `classifyHarborError(...)` for retries. Condition reasons live in `api/v1alpha1/common_types.go`; add new ones there.
- Events: `changeReason(...)` picks `Updated` vs `DriftCorrected`.
- Secrets are never logged, never put in status or events.
- Tests: extend the fake server when adding endpoints; add an envtest scenario per behaviour; keep `make lint` at 0 issues (gocyclo threshold 40, `sort` package forbidden, use `slices`).
- After editing `*_types.go`: `make manifests generate`. Do not edit generated files.

## Harbor behaviour found by the end-to-end suite

The client and the fake server follow these; keep them in sync.

- `GET /system/gc/schedule` returns the parameters as a JSON string in `job_parameters`, and an empty 200 body when no schedule is set.
- `GET /retentions/{id}` of a deleted policy returns 500 on every version. The operator treats a 500 with a healthy `/systeminfo` as missing.
- `DELETE /retentions/{id}` clears the project's `retention_id` on 2.14 and later, but leaves it on 2.12 and 2.13.
- An unknown user on a member POST returns 404.
- Webhook policy GET returns `auth_header`.
- Pushing a manifest identical to one deleted earlier fails with `MANIFEST_UNKNOWN` on 2.15, so e2e images are unique per push.

## Branches and releases

See `CONTRIBUTING.md`. Work branches (`feat/`, `fix/`, `chore/`, `docs/`) are cut from `develop` and squash-merged into it; `develop` merges into `main` for a release, and a `vX.Y.Z` tag on `main` runs `.github/workflows/release.yml`.

## Commands

```
make test                 # client tests + envtest controller suite (downloads envtest binaries once)
make lint                 # golangci-lint
make manifests generate   # after type changes
make run                  # against current kubeconfig
make test-e2e             # kind + Harbor chart (HARBOR_CHART_VERSION, HARBOR_VERSION)
make build-installer      # dist/install.yaml for IMG (default: the release image for VERSION)
```
